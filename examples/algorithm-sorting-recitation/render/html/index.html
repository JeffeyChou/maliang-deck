Hard Concept 1: Comparison Lower Bound
Part 1
Any comparison-based sorting algorithm needs Ω(n log n) comparisons in the worst case.

There are n! possible sorted orders for n distinct keys.

Using n! ≥ (n/2)^(n/2): log₂(n!) = Ω(n log n).

5
1. This is one of the main theorems from the end of the slide deck. 2. A comparison sort learns information only by asking yes-or-no questions like whether one element is less than another. 3. That means every possible execution can be represented as a path in a binary decision tree. 4. For n distinct elements, there are n factorial possible final sorted orders. 5. Therefore the decision tree needs at least n factorial leaves, one for each possible ordering. 6. A binary tree of height h has at most two to the h leaves, so two to the h must be at least n factorial. 7. Taking logs gives h at least log base two of n factorial. 8. Using the standard bound n factorial is at least n over two raised to the n over two, we get omega n log n. 9. The exam instinct is simple: if the algorithm only compares elements, it cannot guarantee little-o of n log n for sorting arbitrary distinct keys.

Hard Concept 3: Partition Logic — Sort vs Select
Part 1
Both quick-sort and quick-select partition into L, E, G around pivot x. The difference is what happens next.
Quick-sort
Quick-select
sort both sides
partition S into L, E, G quickSort(L) quickSort(G) return L + E + G
search one side
partition S into L, E, G if k ≤ |L|: select(L,k) elif k ≤ |L|+|E|: return x else: select(G,k-|L|-|E|)
Worst case: pivot is min/max repeatedly → n+(n−1)+...+1 = Θ(n²). Balanced pivots → Θ(n log n).
Average case: random pivot often prunes a constant fraction. Deterministic selection forces a good pivot.
USF COT4400 Analysis of Algorithms
7
1. Quick-sort and quick-select both use the same partition idea. 2. We choose a pivot x and split the input into L for values less than x, E for values equal to x, and G for values greater than x. 3. The difference is what happens after the partition. 4. Quick-sort must sort both L and G, because the goal is a fully sorted sequence. 5. Quick-select only follows the side that can contain the kth smallest element. 6. If k is at most the size of L, we recurse into L with the same k. 7. If k falls between size L plus size E, the pivot value is the answer. 8. If k is larger, we recurse into G with k decreased by the number of elements in L and E. 9. Most mistakes on selection problems come from updating this rank incorrectly.

Hard Concept 4: Stability, Bucket Sort, Radix Sort
Part 1
Stable sort
Equal keys keep their original relative order. This matters when sorting records by multiple fields.
Bucket sort
For integer keys in [0,N−1], place key k into B[k], then scan buckets. Time/space: O(n+N).
Radix sort
To sort pairs lexicographically, stably sort by the less significant component first, then the more significant component.
Radix order trap
Pairs (k,l): stable sort by l first, then stable sort by k. Sorting by k first then l destroys the primary-key grouping and can be wrong.
USF COT4400 Analysis of Algorithms
8
1. This slide groups together three related ideas: stability, bucket sort, and radix sort. 2. A stable sort preserves the original order of records with equal keys. 3. That property is essential when we sort by multiple fields one field at a time. 4. Bucket sort works when keys come from a known integer range, such as zero through N minus one. 5. It places each item into a bucket indexed by its key and then scans buckets in order. 6. The time and space are O of n plus N, so it is good only when the range N is not too large relative to n. 7. For radix sort on pairs, the pass order is the subtle part. 8. To sort lexicographically by major key and then minor key, stably sort by the minor key first, then stably sort by the major key. 9. The stability of the second pass preserves the ordering created by the first pass inside equal major-key groups.

Why Median-of-Medians is Worst-Case Linear
Part 2
The pivot is not necessarily perfect, but it is guaranteed not to be terrible.
Groups of 5
At least half of group medians are ≥ pivot. In each such group, at least 3 elements are ≥ that median.
Discard guarantee
So at least about 3n/10 elements are ≥ pivot, and at least about 3n/10 are ≤ pivot.
Largest recurse
After partition, the recursive side has size at most 7n/10 + O(1).
T(n) ≤ T(n/5) + T(7n/10) + cn The subproblem fractions sum to 0.9 < 1, so total work across levels is a shrinking geometric series ⇒ T(n)=O(n).
Contrast: randomized quick-select is expected O(n); median-of-medians is worst-case O(n).
USF COT4400 Analysis of Algorithms
14
1. Now let us connect the example to the proof idea. 2. The median-of-medians pivot does not have to be the true median of the entire input. 3. However, it is guaranteed to be good enough. 4. Because the groups have size five, at least half of the group medians are greater than or equal to the pivot. 5. In each of those groups, at least three elements are greater than or equal to that group median. 6. This gives a constant-fraction discard guarantee on the high side. 7. A symmetric argument gives a constant-fraction discard guarantee on the low side. 8. As a result, after partitioning, the largest recursive selection subproblem has size at most about seven n over ten, ignoring lower-order terms. 9. The recurrence is T of n at most T of n over five for selecting the pivot, plus T of seven n over ten for the recursive side, plus c n for grouping and partitioning. 10. Since one fifth plus seven tenths is nine tenths, the recursive fractions sum to less than one. 11. That is why the total work is bounded by a shrinking geometric series and the worst-case time is O of n.
